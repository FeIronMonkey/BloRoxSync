# 7.2 Event stream

> **Spec chapter:** How the plugin receives disk-originated live changes.
> **Parent:** [7. External API](07-external-api.md)
> **Index:** [README.md](../README.md)

## GET /v1/events (preferred)

SSE (`Content-Type: text/event-stream`). Query includes `accessToken`. Optional `since` cursor. **Default: omit `since`**, meaning start at the current cursor (**no backlog**). This differs from `GET /v1/changes`, whose `since` defaults to **0** (full backlog since process start). Poll fallback MUST pass the last processed cursor, not rely on the poll default, after the first response.

Each event:

```
id: 12
event: change
data: {"cursor":12,"origin":"disk","op":"upsert","nodeId":"server/Foo","className":"Script","source":"print(1)\n","revision":4}
```

`id` equals `cursor`. Heartbeat: `event: heartbeat` with `data: {}` at least every 15 s so Roblox Studio notices a dead rbx-sync process.

Close reasons as last event when possible: `event: end` with `data: {"reason":"shutdown"|"replaced"}`. `replaced` corresponds to `SESSION_REPLACED`.

The plugin MUST use `HttpService:CreateWebStreamClient` when available ([references.md](../../references.md)).

## GET /v1/changes (fallback)

Non-blocking poll ([§7.1](07.1-http-api.md)). Plugin MUST poll every **200 ms** while connected if the stream is not open. `since` is the last processed cursor.

## Event object

Same JSON as SSE `data` for `event: change`:

| Field | Ops |
|-------|-----|
| `cursor` | always |
| `origin` | always `disk` on this stream (Roblox Studio–originated changes are not echoed here; wire value for that origin remains `studio`) |
| `op` | `upsert` \| `delete` \| `rename` |
| `nodeId` | always |
| `className`, `source` | `upsert` |
| `newNodeId` | `rename` |
| `revision` | after the disk write |

## Error handling

Unauthorized stream: 401, no SSE body. If the stream drops, the plugin MUST fall back to poll, then retry the stream every 2 s.

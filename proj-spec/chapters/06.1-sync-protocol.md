# 6.1 sync-protocol

> **Spec chapter:** Versioned wire contract shared by rbx-sync and the plugin.
> **Parent:** [6. Components](06-components.md)
> **Index:** [README.md](../README.md)

**Package:** `sync-protocol/`  
**Files:** `protocolVersion.txt`, `schema/v1/*.json`, `fixtures/v1/**`

This package has **no daemon**. It is the source of truth for JSON shapes, error codes, and mapping fixtures ([§6.4](06.4-project-mapping.md)).

## protocolVersion

| Parameter | Default | Notes |
|-----------|---------|-------|
| `protocolVersion` | `1` | Integer. Breaking change ⇒ increment. Stored in `protocolVersion.txt` as a single line `1`. |

rbx-sync and the plugin each embed this integer. Handshake compares them ([§7.1](07.1-http-api.md)).

## Error envelope

Every non-success HTTP JSON body MUST be:

```json
{
  "error": {
    "code": "UNAUTHORIZED",
    "message": "human readable"
  }
}
```

Optional fields allowed only when specified by the route (for example `conflicts` on `CONFLICT`).

### Error codes

| `code` | HTTP status | When |
|--------|-------------|------|
| `UNAUTHORIZED` | 401 | Missing/wrong `accessToken` |
| `PROTOCOL_MISMATCH` | 409 | Handshake `protocolVersion` ≠ rbx-sync |
| `PROJECT_INVALID` | 400 | `rbx-sync.json` missing or fails schema |
| `BAD_REQUEST` | 400 | Body fails schema, invalid JSON, or wrong fields for a listed route |
| `NOT_FOUND` | 404 | Path is not a listed `/v1` route ([§7.1](07.1-http-api.md#routes)) |
| `NOT_MAPPED` | 400 | `nodeId` outside configured roots |
| `CONFLICT` | 409 | Stale `baseRevision` |
| `SESSION_REPLACED` | 409 | Stream closed because a newer session connected |
| `IO_ERROR` | 500 | Filesystem read/write failed |
| `PAYLOAD_TOO_LARGE` | 413 | Source exceeds 1 MiB |
| `INTERNAL` | 500 | Anything else |

`GET /v1/health` never returns this envelope on success.

## Auth

| Parameter | Default | Notes |
|-----------|---------|-------|
| Query name | `accessToken` | 64 lowercase hex chars (32 random bytes) |
| Header auth | unused | Do not require custom headers; plugin HttpService header policy is tight ([references.md](../../references.md)) |

## Content type

Requests with a body MUST send `Content-Type: application/json`. Responses with a body MUST use the same.

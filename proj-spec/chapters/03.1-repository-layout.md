# 3.1 Repository layout

> **Spec chapter:** One git repository, the packages it contains, and how they interact.
> **Parent:** [3. Architecture](03-architecture.md)
> **Index:** [README.md](../README.md)

The workspace directory `roblox-sync` is **one git repository**. It holds the system spec and three **packages** (directories). Packages are **not** nested git repositories and **not** git submodules.

## Packages

| Directory | Git repo? | Runtime? | Responsibility |
|-----------|-----------|----------|----------------|
| `.` (this repo) | Yes | No (docs) | `proj-spec/`, `references.md`, `AGENTS.md`, `reviews/`, plus the packages below |
| `sync-protocol/` | No (package) | No | `protocolVersion`, JSON Schema, mapping fixtures, golden request/response JSON |
| `sync-agent/` | No (package) | Yes | `rbx-sync` CLI/daemon: serve, watch, apply disk writes, plugin install helper |
| `studio-plugin/` | No (package) | Yes | Luau plugin: connect UI, DataModel + ScriptEditorService, HTTP client |

This repository’s root and each package directory MUST contain `AGENTS.md` and `README.md` repeating the **source ban** ([§2 G8](02-goals-and-non-goals.md)).

## How they interact

```
sync-protocol  --(schemas + fixtures, version N)-->  sync-agent
sync-protocol  --(same schemas + fixtures)-------->  studio-plugin
sync-agent     --(HTTP /v1  protocolVersion N)---->  studio-plugin
```

1. **sync-protocol** publishes a documented `protocolVersion` integer. Breaking wire or mapping changes increment it.
2. **sync-agent** embeds or vendors the schemas for that version, implements HTTP, filesystem mapping, and watch.
3. **studio-plugin** implements the same mapping tables in Luau and the HTTP client. It does not import Go code.
4. At handshake, both sides send `protocolVersion`. If unequal, rbx-sync returns `PROTOCOL_MISMATCH` and the plugin MUST refuse to sync.

Plugin and rbx-sync MUST NOT import each other’s source. They MAY copy generated types from `sync-protocol` (JSON Schema → stubs) but MUST NOT copy from third-party sync tools.

## This repo vs the user’s project

| Tree | Contains |
|------|----------|
| `roblox-sync` (this repository) | Specs and tool source (packages in this git repo) |
| User’s **project** | `rbx-sync.json` plus mapped `src/` (or other disk roots). A different git repo. The local source tree for IDE editing, **not** the Roblox place file ([§1](01-overview.md#trees)). |

rbx-sync’s `--project` path points at the user’s **project**, never at this tool repo unless someone is dogfooding.

## Bootstrap contents of packages

Stage 0 scaffolding is in place: `README.md`, `AGENTS.md`, `.gitignore`, the Go module under `sync-agent`, `sync-protocol/protocolVersion.txt`, and empty target directories from [§5](05-file-tree.md). No serve binary, no plugin model.

## Versioning

| Artifact | Version |
|----------|---------|
| Protocol | `protocolVersion` in schemas and `rbx-sync.json` |
| rbx-sync binary | Semver recorded in `sync-agent`; CLI `rbx-sync version` prints binary + protocol |
| Plugin | Semver in plugin UI; handshake includes plugin semver as informational metadata |

A plugin MAY talk to rbx-sync with the same `protocolVersion` even if semver differs. Different `protocolVersion` MUST fail handshake.

Independent git remotes per package are **not** used in v1. CI MAY path-filter `sync-agent/**`, `studio-plugin/**`, and `sync-protocol/**`. Release tags MAY be prefixed (`agent/v0.1.0`, `plugin/v0.1.0`) but handshake still uses `protocolVersion` only.

# 10.1 Install

> **Spec chapter:** How a developer gets a working rbx-sync process and plugin.
> **Parent:** [10. Operations](10-operations.md)
> **Index:** [README.md](../README.md)

v1 **user** install is a **one-command** download of checksummed release binaries (G9, D10). Marketplace distribution is allowed later and does not change the wire protocol. Contributor source builds remain supported and are not the default user path.

## Release assets

Each tagged rbx-sync release MUST publish at least:

| Asset | Contents |
|-------|----------|
| `rbx-sync-windows-amd64.exe` | `windows/amd64` rbx-sync (`rbx-sync.exe`) |
| `rbx-sync-linux-amd64` | `linux/amd64` rbx-sync (`rbx-sync`) |
| `rbx-sync.rbxmx` | Packaged plugin |
| `SHA256SUMS` | SHA-256 of the three files above, one path per line |

Asset host is **GitHub Releases for this repository** or an equivalent HTTPS release page documented in the root `README.md`. Scripts MUST NOT download from a host that is not that documented page unless `RBX_SYNC_RELEASE_BASE` is set (tests and mirrors).

## One-command user install

Documented commands (exact URLs filled in `README.md` when the remote exists):

| Environment | Command |
|-------------|---------|
| Windows (PowerShell) | `irm <documented-install.ps1-url> \| iex` |
| Linux or WSL (POSIX sh) | `curl -fsSL <documented-install.sh-url> \| sh` |

Those scripts live in this repo as `scripts/install.ps1` and `scripts/install.sh`. They MUST:

1. Detect OS (`windows` vs `linux`). On WSL, use the **linux** rbx-sync asset.
2. Download the matching rbx-sync asset, `rbx-sync.rbxmx`, and `SHA256SUMS`.
3. **Refuse to install** if SHA-256 of a downloaded file does not match `SHA256SUMS`.
4. Install rbx-sync to a user-writable directory:

| Environment | Destination directory | Binary name | PATH |
|-------------|----------------------|-------------|------|
| Windows | `%LOCALAPPDATA%\rbx-sync\` | `rbx-sync.exe` | Add this directory to the **user** PATH when missing; print that a **new** terminal is required |
| Linux / WSL | `$HOME/.local/bin/` | `rbx-sync` | If `$HOME/.local/bin` is not on `PATH`, print a single `export PATH="$HOME/.local/bin:$PATH"` line; do not rewrite shell rc files |

5. Write `rbx-sync.rbxmx` beside rbx-sync on Windows (`%LOCALAPPDATA%\rbx-sync\rbx-sync.rbxmx`) and to `$HOME/.local/share/rbx-sync/rbx-sync.rbxmx` on Linux/WSL. Run `rbx-sync plugin install` (using the `--file` default in [§7.3](07.3-cli.md)) when Roblox Studio’s plugins folder is reachable ([§6.2](06.2-sync-agent.md#plugin-install-helper)). If the folder is reachable and `plugin install` exits non-zero, the installer MUST exit with that status (MUST NOT exit 0). If the folder is not reachable (typical native Linux without `/mnt/c/…`), print the staged `.rbxmx` path and exit **0** after the rbx-sync install succeeded.
6. Support `--dry-run` (PowerShell: `-DryRun`) that prints destination paths and asset names and **does not** download or write files.
7. Honor `RBX_SYNC_RELEASE_BASE` as the HTTPS directory containing the assets (no trailing-slash requirement beyond what the script documents).

After a successful rbx-sync install, `rbx-sync version` MUST print `protocol=1` when this spec applies (new shells, or the installer’s printed `PATH` hint).

Windows “one-click” in v1 **is** the PowerShell one-liner. A GUI installer is N9.

## Contributor build (optional)

1. Build `sync-agent` for the OS that will **run serve** (`CGO_ENABLED=0`):
   - Native Windows: `GOOS=windows GOARCH=amd64`
   - Linux or WSL: `GOOS=linux GOARCH=amd64`
2. Place `rbx-sync` / `rbx-sync.exe` on `PATH`.
3. Package `studio-plugin` to `rbx-sync.rbxmx` from `sync-agent/`:
   `go run ./cmd/package-plugin -src ../studio-plugin/src -out rbx-sync.rbxmx`
   then run `rbx-sync plugin install --file rbx-sync.rbxmx` (or place the artifact beside the `rbx-sync` binary and omit `--file`).

## Plugin destination

`rbx-sync plugin install` copies `rbx-sync.rbxmx` to:

| Environment | Destination |
|-------------|-------------|
| Windows | `%LOCALAPPDATA%\Roblox\Plugins\rbx-sync.rbxmx` |
| WSL | Destination from [§6.2](06.2-sync-agent.md#plugin-install-helper) (Windows `%LOCALAPPDATA%` via `wslpath`, not a hard-coded username) |

User fully restarts Roblox Studio after plugin copy.

Manual alternative: Plugins → Open Plugins Folder, copy the same file ([references.md](../../references.md)).

## Project

Create `rbx-sync.json` in the user’s project as in [§6.4](06.4-project-mapping.md). Disk root directories MAY start empty. This is the local source tree, not the Roblox place file ([§1](01-overview.md#trees)).

## Health check after install

1. `rbx-sync serve --project <projectDir>`
2. From Windows (or WSL, depending on where rbx-sync listens): HTTP GET `http://127.0.0.1:29850/v1/health` returns `ok: true`.
3. Plugin Connect with the printed token reaches `POST /v1/session`.
